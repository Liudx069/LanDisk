# AUDIT_CORRECTIONS_07 — 首次安装体验：做了什么、边界在哪、哪些没测

本文件对应 `LAN_DISK_SETUP_FIRST_RUN_UX_07`。它记录这一轮**新增**的安装/首次配置能力，
以及为了让这些能力可被审核而明确划出的边界。它不是缺陷更正清单，而是**架构变更说明**：
本轮唯一允许的破坏性变更是一次的证书架构迁移，其余全部是新增。

04/05/06 的报告（`docs/AUDIT_CORRECTIONS_04.md`、`docs/AUDIT_CORRECTIONS_05.md`、
`docs/AUDIT_CORRECTIONS_06.md`、`docs/DELIVERY_REPORT.md`）保持原样，未作任何修改。

## 1. 证书架构：从"一个自签 leaf"到"持久根 CA + 短命 leaf"

### 旧状态（1.3.0）

`CertificateService` 生成一个自签证书：`CN=LanDisk (<计算机名>)`，有效期 3 年，SAN 里写死了安装
当天的那几个局域网地址。后果是：

- DHCP 换地址后，Safari 会报证书错误，用户必须重新走一遍"下载证书 → 安装描述文件 → 打开完全信任"；
- 证书与 IP 绑死，所以"换个网络就能用"这件事在结构上不成立。

### 新状态（1.4.0）

| 角色 | 有效期 | 更换时机 | 谁能看到私钥 |
|---|---|---|---|
| LanDisk 本地根 CA | 10 年 | 到期 / 私钥损坏 / 用户主动重置 | 只有本机当前 Windows 用户（DPAPI 封存） |
| 服务器 leaf | ≤397 天，到期前 30 天自动续签 | 缺失、签发者不符、即将到期、SAN 未覆盖当前地址 | 同上 |

关键不变量：**根 CA 不随版本更新、IP 变化、leaf 续签而改变**。手机信任的是根，所以只信任一次。
`EnsureLeaf` 每次都会重新判断"现有 leaf 能不能服务当前这组名字与地址"，不能则重新签发；
判断依据是 AKI/SKI 的密码学对应关系，而不是 issuer 字符串，因此显式重置 CA 之后旧 leaf 不会被误用。

私钥落盘形式：DPAPI（`CryptProtectData`，当前用户）封装的 PKCS#12，通过 P/Invoke 直接调用
crypt32，不引入额外 NuGet 依赖。选择 DPAPI 而不是 CNG 不可导出密钥的理由写在
`LocalCertificateAuthority` 的文档注释里：运行时私钥必然在进程内存中，"不可导出"不是本产品能诚实
宣称的性质，而 DPAPI 能诚实地宣称"落盘字节对其它账户无用"。

### 一次性迁移

检测到 1.3.0 的 `tls\landisk.pfx` 时：先建立新层级并确认可用，再把旧文件整体归档到
`tls\legacy-1.3.0-<时间戳>\`，然后在 `install.json` 里记下迁移已完成（只执行一次）。
**不**静默假装旧 iPhone 的信任可以转移到新根——那在密码学上就是不成立的。

## 2. 稳定名称与 mDNS：为什么自己实现

需求是"手机用 `https://landisk-xxxxxxxx.local:8892` 长期访问"，且**不得要求用户安装 Bonjour
或任何常驻第三方服务**。可选方案与取舍：

- 第三方 .NET mDNS 库：引入一个会随版本漂移的依赖，且它同样需要自己管理 announce/goodbye 与冲突；
- 系统级 Bonjour：明确禁止；
- 自己实现足够小且有测试的 responder：本轮选择。

实际需要的表面很窄：回答**关于自己名字与自己服务**的问题、启动时宣告、退出时说再见、发现名字冲突。
因此实现分两层：

- `DnsMessage`（线格式编解码，读取支持压缩指针，写入不压缩）与 `MdnsRecords`（记录构造，纯函数）；
- `MdnsResponder`（UDP 5353 收发、announce/goodbye、冲突检测）。

测试覆盖的是**会出 bug 的那一层**：编解码往返、压缩指针、记录内容、只回答自己的名字、
冲突判定、TXT 不含秘密。组播能否加入取决于网络环境，因此 `Start()` 返回失败原因而不是抛异常：
失败时电脑界面明确显示"稳定名称不可用"并回退到地址二维码，**绝不**偷偷降级成明文 HTTP。

冲突处理：收到别人对自己名字的 A/AAAA 声明且地址不是自己的 → 提升一个持久后缀并保存，
此后保持不变。它不会每次启动重新随机。

## 3. 首次连接引导：明文 HTTP 能做什么，不能做什么

8890 端口是一个**临时的、只服务四类静态内容**的明文 HTTP 监听：

| 允许 | 禁止 |
|---|---|
| 静态引导页（中文步骤说明） | 管理接口 / admin token |
| 公开的根证书（`.cer`、`.mobileconfig`） | 文件接口 / 文件内容 |
| "HTTPS 是否已受信任"的布尔状态 | Cookie / 长期设备 secret |
| | 任何配置变更 / 更新上传 |

实现上没有使用 `HttpListener`（非回环前缀需要 URL ACL 或管理员权限），而是一个只处理 GET 的
极小 TCP HTTP/1.1 响应器：**逐地址绑定**到私网地址（不是 `0.0.0.0` 再靠防火墙兜底），
向导关闭或超时后立即停止监听。

配对令牌不进明文页面。流程被刻意拆成两个二维码：第一个是 8890 的引导地址（无秘密），
苹果强制的"完全信任"由用户本人在 iPhone 上完成后，页面通过加载
`https://<host>:8892/api/onboarding/trust-probe?b=<id>` 证明 TLS 已经可用；
只有这时电脑上才会出现**第二个**二维码，携带一次性配对令牌，走 HTTPS。
把令牌放进明文页面对用户更方便，也等于把它交给同一个局域网里的任何人。

`.mobileconfig` 只包含公开根证书，设置了唯一的 `PayloadIdentifier`，不设置 VPN / 代理 / MDM，
也不禁止移除。无法合理签名就如实显示 iOS 的"未签名描述文件"提示，不伪造组织签名。

## 4. 防火墙：一次 UAC，两个固定动作

- 普通安装流程全部以当前用户运行（程序写入 `%LOCALAPPDATA%`、快捷方式、卸载注册都在 HKCU）。
- 只有防火墙需要一个 elevated 子进程：重新以 `runas` 启动**同一个可执行文件**，
  参数固定为 `--elevated-firewall-add` 或 `--elevated-firewall-remove`。
- 该模式自己从 `FirewallPlan` 与**默认安装目录**重建规则，不接受调用方传入的任何规则文本、路径或命令；
  `SetupOptions.Validate` 会拒绝非默认目录与同时指定两个动作。
- 规则只有三条，全部 `dir=in action=allow profile=private remoteip=localsubnet`：
  TCP 8892（HTTPS）、TCP 8890（仅向导）、UDP 5353（mDNS，仅此一个组播端口）。
  三条都绑定到安装目录中的 `LanDisk.exe` 这一具体程序路径。**管理端口 8891 不在任何规则里。**
- 旧的手工解压版本可能创建过指向 `LanDisk.Server.exe` 的规则：本轮只**报告**它们，不静默删除。
- 卸载只删除名称由本产品生成的规则（`LanDisk` 前缀）。

审计方式：`LanDisk-Setup.exe --print-firewall-plan` 不需要管理员权限就能打印出全部
`netsh` 参数与不变量检查结果；单元测试对同一份计划断言"仅 Private / 仅 LocalSubnet / 不含 8891 /
不含端口范围"。

## 5. 安装器：为什么是"staging + 校验 + 替换 + 可回退"

`LanDisk-Setup.exe` 内嵌的就是被测试过的 `LanDisk-win-x64.zip`，并在程序集元数据里记录它的
SHA256；安装器在写入任何字节之前先核对这个摘要，再解压到暂存目录，逐项确认"解压出来的东西
就是 `install-manifest.json` 声明的东西"（包括 06 轮建立的 `buildInfo` 记录：path/bytes/sha256）。

只有全部通过之后才会动安装目录，并且：

1. 先把要被替换/删除的文件备份到同级备份目录；
2. 逐文件"写到 `.new` 再 Move"，避免留下半个可执行文件；
3. 只删除**上一份清单声明过**的文件——用户自己放进程序目录的东西永远不会被删；
4. `install-manifest.json` 最后写入，因此中断的安装仍然是可恢复的；
5. 任何一步失败 → 从备份回滚，并明确报告"安装目录未被改动"。

安装器自身会在安装目录留一份副本，供"已安装的应用"里的卸载入口使用；该副本**不列入**
`install-manifest.json`，因此未来的 `.lupd` 升级不会把它当作过期文件删除。

选择"内嵌 95 MB 载荷"+ "安装目录再放一份安装器"而不是"解压一整个文件夹"，代价是磁盘占用，
换来的是用户侧只有一个文件、以及"装上去的东西就是被测试过的东西"这句可验证的话。

## 6. 本轮明确未做

- **Authenticode 代码签名**：没有可信代码签名证书，因此报告 `AUTHENTICODE = NOT_CONFIGURED`。
  用自签代码证书冒充正式发行签名会让 SmartScreen 的表现更像"已签名"，是误导，不做。
- **Setup 自更新**：本轮不联网获取新的安装程序。
- **IPv6 mDNS**：responder 只加入 IPv4 组播组（`224.0.0.251`）；发布的是 A 记录。
  AAAA 的记录构造与解析已实现并有测试，但本轮不在真实链路上宣告。
- **真实 UAC / 真实防火墙生效**：需要交互式提权，验收脚本把它记为 `NOT_RUN`，不伪造 PASS。
- **真实 iPhone / 物理移动硬盘 / 客户端信任**：仍是 `NOT_RUN`，整体状态 `READY_FOR_DEVICE_VALIDATION`。
