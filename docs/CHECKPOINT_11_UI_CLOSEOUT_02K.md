## 3. 本段完成项：页面身份锚点（第二节）

### 3.1 补上的第二个覆盖漏洞
上一段把"数量比较"升级成集合比较，但期望的**页面名单**仍是从结果行推导的，于是还有第二种伪造方式：
**把某个必需页面的全部结果替换成一个不存在的页面** —— 总行数与页面数量都保持不变，数量校验看不出。

### 3.2 修法
- `src/LanDisk.App/UiCapture.cs` 新增输出 **`UI_PAGE_CATALOG.tsv`**：由产品自己的
  `PageCatalog.All` 逐条写出 `title / pageType / group`，并带构建身份
  （`# version` / `# commit` / `# buildId`，取自 `BuildInfo`）。
  它与"实际渲染了什么"无关，所以不能被结果反过来定义。
- `tools/EvidenceVerdict.ps1` 改为要求：
  1. 目录存在且非空；
  2. 目录声明的 `commit` 必须等于当前候选（**为空也阻断**：无法确认它属于当前候选）；
  3. 摘要的页面总数（`NAV_PAGE_COUNT` / `UI_CAPTURE_EXPECTED`，两者必须一致）必须与目录条数相符；
  4. 实际页面集合必须与目录集合**相等** —— 缺页、**未知页/身份不符**分别阻断；
  5. 仍逐页要求组合数恰为 42，并做 主题|缩放|尺寸|页面 的集合差（缺项/重复项/额外项）。
