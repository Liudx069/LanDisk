### B1. 重叠反例（REAL11-05）— **已证明**
- 定向运行：单页面 `文件与共享` + 1600x900 + 1.00x + Dark + 隔离夹具，15 个组合（非 630）。
- 用 `RenderTransform` 把第二个可见按钮真正平移到第一个之上；`BoundsWithin` 走
  `TransformToAncestor`，包含该变换，所以相交既真实又可测量。
- **注入探针（检测之前写盘）**：`开启开机启动` vs `删除快捷方式/开机启动的检查`，
  平移后矩形 `122,146,211,33`，**相交 6×33 DIP**。
- **检测结果**：`LAYOUT-ACTION-OVERLAP` 目标 2885、**失败 7**；`LAYOUT-BUTTON-SPACING` 失败 **0**
  —— 失败落在正确的断言上，不是被间距门禁顺带抓到。退出码 **2**。
- 证据：`dist/evidence-11/DIAGNOSTIC-injection-overlap/`

### B2. 核心值截断反例（REAL11-03）— **已证明，过程中修正了我自己的错误**
- **第一次尝试是错的**：用 `FormattedText` 度量"文字本来需要多宽"，它系统性偏大几 DIP，
  在干净矩阵上把 `v1.7.3`、`局域网访问尚未开启` 这类正常值报成截断（**10 处误报**）。
  在正确布局上乱报的检查比不响的检查更糟，因此该度量方式被弃用。
- **改为**用一个无限宽约束的一次性 `TextBlock` 重新测量（走页面同一套文本栈）。
  干净矩阵 630 组合、**4324 个核心值 → 误报 0**。
- **再用同一注入跑**：探针记录 `局域网访问尚未开启` 自然宽 **108 DIP → 实际 36 DIP**、
  `v1.7.3` 72 → 37、`Online` 37.8 → 20，即真实可见的裁切。
  检测：`LAYOUT-CORE-VALUE-NOT-CLIPPED` 目标 101、**失败 10**，其余断言全部 0 失败。退出码 **2**。
- **同时修掉旧实现的根本问题**：它拿 `ActualWidth` 和 `DesiredSize` 比，而 `DesiredSize` 已被
  测量约束夹住，所以那种写法**在结构上无法发现**"窄列里被省略号截断"——正是 Owner 拍照的那一类。
- 证据：`dist/evidence-11/DIAGNOSTIC-injection-clip/`、`dist/evidence-11/DIAGNOSTIC-clipcheck-none/`
