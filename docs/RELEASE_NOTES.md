# LanDisk 1.8.1

1.8.1 是稳定性补丁，修的都是"出问题时产品一声不响"的地方。

## 这一版修掉的问题

- **手机突然连不上，而电脑上看不出任何异常**：如果你在「网络」里固定过绑定地址，之后换了网络或 DHCP
  把这个 IP 换走了，旧版本会去绑一个已经不存在的地址，绑定失败后**静默退化成只监听本机**，日志里
  一个字都没有。现在：
  - 固定地址失效时**自动回退**到当前物理网卡，局域网继续可用；
  - 网络页会明确写出"你固定的 X 已不在任何网卡上，本次已自动回退"；
  - 日志里同时留一条记录，不会再出现"看起来在跑、手机就是连不上"。
- **扫码能进、浏览器却要求重新配对**：配对凭据按主机名隔离，二维码编的是 `.local` 名称，用 IP 打开
  就是另一个主机。现在配对页会直接写出**这个二维码指向哪个地址**，并提示"手机以后请一直用这个地址"；
  同时把其它可用地址列在折叠区（只显示域名/IP，不显示一次性令牌）。
- 6 位配对码的等待阶段仍是"需要在本机管理页点确认"，这一版把配对页的说明写得直白，不再让人以为是卡死。

## 没有变化的

- 安全边界、端口模型、权限模型、回收站、更新签名与自动回滚全部不变。
- 升级保留安装 id、稳定名称、根 CA、已配对设备、共享、回收站与更新密钥，**不需要重新配对**。

## 已知未完成

- 真机项（真实 iPhone 上的主题、删除入口、视频解码，真实 UAC 建防火墙规则）仍需你在手机上确认。
- 同名设备不合并：同一台手机每换一个主机名配对，就会多一条设备记录。

# LanDisk 1.8.0

1.8.0 是 1.7.7 的真机修复版：三处"在 Windows 上看着正常、到 iPhone 上就不对"的问题被定位到根因并修掉，
WiFi 管理按你的决定从产品里完整移除。

## 这一版修掉的问题

- **手机界面泛粉 / 颜色全错**：调色板用 `#AARRGGBB`，CSS 的 8 位十六进制是 `#RRGGBBAA`，写入时 alpha
  被当成了红色通道（浅蓝变浅粉、强调色变品红、灰色接近透明）。现在写入前统一转成 `rgb()/rgba()`。
  桌面预览一直正常，所以这个缺陷只在手机上出现。
- **Windows 上打开「允许删除」后，iPhone 不出现删除入口**：共享能力变化没有推进设备的权限修订号，
  手机只在修订号变化时才重读权限。现在共享能力或启用状态真的变化时会通知已配对设备，**不需要重新配对**。
- **WiFi 管理完整移除**：左侧导航、WiFi 页面、`/api/network/wifi*` 接口、手机端 WiFi 面板、
  `NetworkManage` 权限开关全部删除，产品运行时不再调用 `wlanapi.dll`。
  旧配置里的能力位保留（退役为 `RetiredNetworkManage`），旧设备记录可以正常读取，不会被静默误读。
  要给电脑切 WiFi，请直接用 Windows 任务栏。

## 没有变化的

- 以太网 / 局域网部分一点没少：物理网卡识别、LAN HTTPS 监听、稳定主机名、VPN/TUN 与虚拟网卡排除都保留。
- 安全边界不变：8891 管理端口仍只对本机回环开放，8892 是手机 HTTPS，8890 只在配对期间临时开启。
- 升级保留安装 id、稳定名称、根 CA、已配对设备、共享、回收站、端口与更新密钥，不需要重新配对或重新信任证书。

## 已知未完成

- 扩展程序与命令中心（P19）未交付，界面上没有该入口。
- 真机项（真实 iPhone 上的主题/删除入口/视频解码、真实 UAC 建防火墙规则）仍需你在手机上确认，自动化侧记为 `NOT_RUN`。
- 绑定地址失效时产品仍会静默退化成只监听本机（日志无告警），建议做路由器 DHCP 保留或固定使用 `.local` 地址。

# LanDisk 1.7.0

1.7.0 是产品化版本：界面系统重建、权限语义修正、在线状态、运营看板与完整主题系统。
它不是 1.6.4 的小补丁 —— 升级后窗口、安装器与页面都换了样子，但**数据与配对完全保留**。

## 这一版修掉的用户可见问题

- **安装器不再像内部工具**：深色 Deployment Console，进度是六个服务器节点灯，只在对应阶段真实完成后才点亮；高级日志默认折叠。
- **安装完成不再打开浏览器**：完成页的「打开 LanDisk」只启动 LanDisk 程序（最大化），「连接 iPhone」直接停在原生向导页。Web 管理页 `/admin` 只保留为高级恢复入口，需要明确确认才会打开。
- **主窗口启动即最大化**，可随时还原；窗口变窄时页面按优先级降级，不再出现文字竖排、按钮换行、表头与数据错位、长 ID 撑爆页面。
- **设备页 / 共享页 / 网络页 / 自检页 / 日志页 / 概览页重做**：单一列宽定义、行内详情、状态用图标 + 文字、日志页有级别/分类/时间/关键词过滤与分页、自检页按子系统分组、概览首屏只留六个核心卡片。
- **权限改动立即生效**：把手机从只读改成读写后**不需要重新配对**，下一次请求就能上传；从读写改成只读后，下一次写入立即被拒绝，**正在进行中的上传会被取消**，不会出现"权限已经收回但文件还是写完了"。
- **真正的在线状态**：15 秒心跳 + 每次请求都算活动；45 秒内在显示为在线，5 分钟内为最近活动，超时为离线，已撤销的设备永远不是在线。
- **配对完成页推荐真正可达的地址**：开着 VPN/TUN 时不再推荐刚刚打不开的稳定名称，而是本次连接验证过的物理地址，并把稳定名称标为备用。
- **视频播放器补上全屏按钮**（页面内按钮，优先使用 iPhone Safari 的原生全屏能力）。
- **手机端入口整理**：底部导航包含文件 / 最近 / 收藏 / 传输 / 回收站 / 我的；只读时上传、重命名、删除、新建按钮变为禁用并说明原因。
- **新增运营看板**：运行时长、CPU、内存、实时上下行与 5 分钟折线、存储、在线设备、当前传输、今日流量与请求统计、VPN/HTTPS/证书状态、最近警告与错误。
- **新增设置页的运行配置**：逐项显示「当前生效值 / 持久化值 / 是否需要重启」，不再是"改了就以为生效"。
- **完整主题系统**：跟随系统 / Obsidian / Graphite / Midnight / Arctic + 自定义；Windows 外观与 iPhone 外观分开配置，**iPhone 的配色由这台电脑决定**，手机自动应用。自定义主题只填三个颜色，其余自动派生，并在保存前做对比度检查（不合格会被拒绝并指出原因）。
- **设备管理能力**：写入共享、网络管理、扩展安装、扩展执行、查看系统信息都是**独立**开关，默认全部关闭，与只读/读写是两回事。

## 安全边界没有变化

8891 管理端口仍然只对本机回环开放；8892 是手机 HTTPS；8890 是配对期间的临时引导端口，配对成功即关闭；5353 mDNS 仍然只绑定物理网卡。
配对、令牌、会话 epoch、CSRF、路径安全、回收站、更新签名与回滚、证书模型全部保持原语义。不开放公网，不操作用户 VPN，不改系统路由。

## 升级说明

- 从 1.6.3 / 1.6.2 / 1.6.1 / 1.6.0 / 1.5.0 升级：安装 id、稳定名称、根 CA、已配对设备、共享、回收站、端口与更新密钥全部保留；**不需要重新配对，也不需要重新信任证书**。
- 现有设备的权限不会被扩大：新增的管理能力字段在旧数据里不存在，读取为"全部关闭"。
- 主题：升级后默认仍是"跟随系统"，与 1.6.x 的行为一致；想换主题请在 设置 → Windows 外观 / iPhone 外观 中选择。

## 已知未完成

- **WiFi 管理（P18）未实现**：需要 `wlanapi.dll` 原生实现，且在不得泄漏密码、不得真的切断当前网络的前提下完成自动化验证，本轮条件不具备。界面上没有该入口。
- **扩展程序与命令中心（P19）未实现**：需要独立的受限子进程与完整的安全批准流程，本轮未交付。界面上没有该入口。
- 视频全屏、WiFi 真实连接、扩展真实执行需要真机验收（NOT_RUN）。
- 安装器的视觉缺陷已修复，但宿主仍是 WinForms + 自绘，不是 WPF/XAML（见 `docs/AUDIT_CORRECTIONS_10.md`）。
