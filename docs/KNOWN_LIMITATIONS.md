# 已知限制与非目标

本文件只写实际存在、会影响使用或影响结论可信度的事项，不做「都支持」式的模糊表述。
每条都标明当前状态。

> 版本 1.1.0（`LAN_DISK_DSH_UX_AUTH_UPGRADE_02`）新增的限制集中在第 6 节。

## 3. 协议与兼容性上的明确取舍

### 3.1 上传分块必须严格按顺序

- 服务端只接受 `offset == 已接收字节数` 的分块；乱序分块返回 `409` 并带上服务器期望的偏移。
- 这是为了让「续传」有唯一的、可验证的语义。代价是：不支持并行上传同一文件的分块。
- 同一个设备可以同时上传多个不同文件（默认上限 4 个会话）。

### 3.2 续传的校验强度

续传要求客户端提供两样东西：

1. **内容指纹**：长度 + 修改时间 + 文件头 64 KiB 的 SHA-256 + 文件尾 64 KiB 的 SHA-256。
2. **前缀哈希**：服务端已接收字节的 SHA-256（服务端会重新读取暂存文件自行计算，不信任客户端声明）。

因此「同名同大小但内容不同」的文件无法拼接到旧会话。理论上的残余风险是：
两个文件长度相同、头尾 64 KiB 相同、且已接收前缀相同——这种组合实际上要求它们在中段恰好一致才可能被误判，
而中段在提交时仍会做整文件 SHA-256 校验，所以不会落盘成损坏文件。

浏览器端在「已接收前缀超过 256 MiB」时不重新计算前缀哈希（避免在手机上长时间读盘），
此时会提示改为重新上传，而不是悄悄跳过校验。

### 3.3 多区间 Range 请求

`Range: bytes=0-99,200-299` 这类多区间请求会被忽略并按完整实体返回 `200`。
这是 RFC 9110 允许的行为，且避免实现 multipart/byteranges。单区间、后缀区间、
开放区间、`If-Range`、`If-None-Match` 都按规范实现。

### 3.4 版本令牌的容差

列表里的「版本」是 `长度-修改时间`。写入前的复核中，长度必须完全一致，
修改时间允许 2 秒误差——因为 FAT/exFAT（移动盘常见）的目录项会缓存且有 2 秒时间粒度，
否则会出现用户什么都没做却报「对象已变化」的误报。这比句柄级对象 ID 弱，但配合
「所有写入都通过已校验句柄执行」，实际操作对象不会跑偏。

### 3.5 硬链接

文件有多个硬链接（`nNumberOfLinks > 1`）时，**拒绝**改名和删除，因为修改它可能影响共享目录之外的对象。
读取不受影响。这是保守取舍，不是缺陷。

### 3.6 重命名/删除的 TOCTOU 处理

改名与删除使用 `SetFileInformationByHandle` + `FILE_RENAME_INFO`，
操作对象是已经过最终路径、卷身份、重解析点校验的**句柄**本身，
所以「校验与执行之间路径被替换」不能把操作重定向到别的文件。

### 3.7 网络设置的生效时机

监听地址与端口在**启动时**确定。修改网络设置后必须重启程序才会生效，
管理页会明确提示。这是为了避免运行中意外地把服务暴露到新的网卡上。

## 4. 存储与部署

| 项 | 说明 |
|---|---|
| 内部目录位置 | 共享所在卷根目录下的 `.landisk-data\`。这是 LanDisk 的内部暂存与回收区，不会出现在任何列表里，也无法通过任何接口访问。停止程序后可手动删除（会丢失回收站内容）。如果卷根不可写，会退回到 `%LOCALAPPDATA%\LanDisk\store\` 并改用「复制+校验」的跨卷回收流程。 |
| 跨卷回收 | 当共享目录与存储目录不在同一卷时，删除会走「带日志的复制+校验后删除原文件」流程；崩溃窗口中对账只会丢弃自己的暂存副本，绝不会删除用户仍然拥有的原文件。这是可用性上的降级，速度比同卷改名慢。 |
| 上传会话的生命周期 | 会话保存在进程内存中。程序重启会丢失未完成的上传（暂存文件会在下次启动时被清理）。刷新浏览器不会丢失。 |
| 暂存配额 | 默认为「卷可用空间的 1/4，且不超过 50 GiB」，可在配置中调整。超出时报明确错误，不产生假成功。 |
| 没有安装程序 | 交付形式是自包含目录运行包，不写注册表、不建服务、不加开机启动。升级 = 替换程序目录。 |

## 5. 安全上的如实说明

- 应用以**普通用户**权限运行，不会为了读取受保护文件而提权。
- 不防御已经控制宿主机或当前 Windows 账户的攻击者。
- 隐藏属性不是保密措施；本应用不依赖隐藏属性做任何访问控制。
- 卷 GUID 用于「区分不同磁盘」，**不是**密码学凭据；恶意克隆的磁盘理论上可以伪造卷身份。
  卷身份用于防止「误操作写到另一块盘」，不用于对抗有物理访问权的攻击者。
- HTTP 兼容模式下，同一局域网内的攻击者可以截获或篡改传输内容。配对令牌、CSRF、权限校验都不能改变这一点。
- 撤销设备无法收回手机已经下载或缓存的数据。
- 回环管理入口依赖「只有本机进程能访问回环」这一操作系统边界；同一台电脑上的其他用户进程属于既有信任边界之内。

## 6. 环境相关

- 开发机没有安装 ffmpeg；合成媒体样本是通过 Python 包 `imageio-ffmpeg` 附带的 ffmpeg 静态构建生成的
  （仅用于生成测试数据，**不是**运行时依赖）。
- Playwright 的 Chromium 构建不包含 H.264 等专有编解码器，因此真实解码/拖动验证使用 VP9/Opus 与 PCM。
  MP4/H.264 的真机播放能力记为 `NOT_RUN`。
- `<4 GiB` 以上的大文件上传测试需要显式打开环境变量 `LANDISK_BIGFILE_TEST=1` 才会运行，
  以避免每次常规测试都写入数 GB 数据。是否实际运行见最终报告。

## 6. 本轮（1.1.0）新增能力的限制

### 6.1 搜索与「最近」是有上限的扫描，不是索引

LanDisk 不建立全盘索引，也不写入任何后台数据库。跨文件夹搜索与「最近」都是**按需遍历**：
从已经通过权限校验的目录出发，逐层枚举，遇到上限就停止并在响应里明确标记 `truncated`。

| 项 | 默认值 | 说明 |
|---|---|---|
| 单次搜索最多检查的目录项 | 200 000 | 达到上限会截断并提示，不会假装结果完整 |
| 单次搜索最多保留的匹配项 | 20 000 | 超出部分不会返回 |
| 递归深度上限 | 32 层 | |
| 「最近」窗口 | 30 天（可配置） | 只包含文件，不包含文件夹；不记录浏览历史 |
| 「最近」扫描结果缓存 | 20 秒 | 上传/改名/删除/恢复会立即失效缓存 |

在超大共享（数十万文件）上，第一次跨文件夹搜索会有可感知的等待；结果会被缓存 20 秒。
这是可以接受的取舍，但**不是**「瞬时搜索」。搜索只按名称匹配，不做文件内容检索。

### 6.2 缩略图依赖 Windows 图像管线，并且是有界的

- 缩略图使用 `System.Drawing.Common`（GDI+，MIT，Windows 专用）在本机解码并与缩放，
  **不执行文件内容**，也不把 SVG 栅格化（SVG 属于主动内容，永远只作为附件下载）。
- 只对扩展名在白名单内、且文件大小不超过 64 MiB、像素不超过 1.2 亿的图像生成缩略图；
  超出范围或解码失败的会明确返回错误，前端退回普通图标。
- 缩略图缓存在 `%LOCALAPPDATA%\LanDisk\thumbs`，默认上限 256 MiB，超出后按最后写入时间淘汰。
- **图像解码本身是攻击面**。LanDisk 只解码由已配对设备请求、且位于已授权共享内的文件，
  并设置了大小与像素上限；但这不等于对恶意构造图片的完整防护。

### 6.3 批量下载 ZIP 的边界

- 单个归档默认最多 20 000 个条目、总大小 32 GiB（都可配置）。达到上限会**明确标记截断**，
  并把未能包含的项目写进归档内的 `_LanDisk_未包含的项目.txt`。
- 归档由服务器流式生成，逐文件读取、逐文件写入，峰值内存是一个缓冲区加上压缩器状态，
  与选择的总大小无关。
- 归档内容按共享内相对路径组织，ZIP 条目名会去掉路径分隔符、盘符与保留字符，
  不会出现可以逃出解压目录的条目名。
- 计划阶段已经校验过每一个条目；如果在**流式写入过程中**文件被替换或读取失败，
  该条目会不完整并记录在归档内的 `_LanDisk_传输中断的项目.txt` 中——不会有假成功，
  但 ZIP 格式本身无法在流中断之后再撤回已经写出的条目。

### 6.4 浏览器下载文件名的引擎差异

服务器按 RFC 6266 同时发送 `filename*=UTF-8''…`（优先）与一个可读的 ASCII 回退名
（例如把「界面测试共享-20260927-004502.zip」回退为「20260927-004502.zip」，而不是一串下划线）。

- Chromium 采用 UTF-8 名，下载得到的文件名保留中文。
- **Playwright 的 WebKit 只采用 ASCII 回退名**。这是该引擎在下载建议名上的行为；
  真实 iOS Safari 的对应行为**未在本机验证**，记为 `NOT_RUN`。
  无论名字如何，**归档内容与文件本身不受影响**。

### 6.5 长按与多选

- 手机上长按约 450 毫秒进入多选；桌面上是右键，或从 `…` 菜单选「选择」。
- 长按依赖指针事件。如果某个浏览器扩展或辅助功能工具拦截了长按手势，请改用 `…` 菜单里的「选择」。

### 6.6 本机管理端「自动进入」的信任边界

- 管理端的自动进入依赖「只有本机进程能访问回环地址」这一操作系统边界，
  并额外要求请求是同源页面（校验 `Origin` 与 `Sec-Fetch-Site`，且**完全不读取**任何转发头）。
- 因此，**同一台电脑上已经控制当前用户会话的其他程序仍然可以访问管理端**。
  这与「本机管理员属于既有操作系统信任边界」是同一件事，LanDisk 不声称能防御它。
- 局域网上的手机无法访问管理端（非回环来源一律 403）。
- 一次性恢复令牌仍然保留，但已不在正常流程中出现。

### 6.7 其他

- 收藏按**设备身份**保存，换一台手机不会继承；共享被删除时，指向它的收藏会一并移除。
- 界面偏好（排序、列表/网格）按设备保存在 `%LOCALAPPDATA%\LanDisk\preferences.json`。
- 批量删除有单次条目数上限（默认 500 项），本轮**没有**批量永久删除。
- 本轮**没有**新增：双向同步、自动照片备份、文件版本历史、OCR/AI 索引、在线 Office 编辑、
  完整审计中心、PWA 离线文件缓存、多用户组织、SMB/NFS/WebDAV 服务端、公网访问。
  这些可以作为后续候选，但本轮不实现。

## 7. 任务 03 新增能力自身的限制

### 7.1 桌面应用

- `LanDisk.exe` 是 WinForms 外壳，**仅支持 Windows**（发布目标 `win-x64`）。托盘图标、单实例与
  开机启动都依赖 Windows 的通知区域与注册表。
- 单实例的范围是**同一个 Windows 用户**（命名互斥体为 `Local\...`）。两个不同的用户各自的会话里
  可以各跑一份，此时第二份会因为 8891/8892 被占用而启动失败——这是刻意的：**LanDisk 不会自动改端口**。
- 开机启动项写的是**当前用户**的 `HKCU\...\Run`。以管理员身份运行或以别的用户登录时看到的状态不同。
- 外壳没有控制台，所以**看不到实时日志**；日志在 `%LOCALAPPDATA%\LanDisk\logs\landisk.log`。
- 托盘图标与窗口在"以服务方式运行 / 无交互会话"的环境里没有意义；
  那种场景应当直接使用 `LanDisk.Server.exe`。

### 7.2 系统更新

- **只在 Windows 上**、并且只在安装目录可写时可用。安装到 `Program Files` 之类需要管理员权限的位置时，
  更新会因为在写入阶段失败而回滚（程序不会请求提权）。
- 更新前必须有一个 `updater\LanDisk.Updater.exe`。从更早的版本（只有 `LanDisk.Server.exe` 的
  01/02 版发布包）升级时，如果那个目录里没有 updater，管理页会明确提示"自动更新与自动回滚不可用，
  请使用完整安装包升级"，并且**拒绝**应用更新——半途而废的更新比不更新更糟。
- **不是增量更新**：`.lupd` 包里是完整的程序文件，1.2.0 的包约 95 MB（原始约 181 MB）。
  只传输变化的文件需要另一套协议，本版本不做。
- **只做程序文件**：不迁移数据、不改数据库、不管理多个已安装版本；同一台机器只维护一份安装。
- **没有自动检查更新**：LanDisk 不联网查询版本，也不在后台自动安装。更新必须由人上传并按确认。
- **没有卸载程序**：删除安装目录即可；`%LOCALAPPDATA%\LanDisk` 里的共享配置、配对设备与备份需要手动删除。
- **回滚只保留最近 3 份备份**（`updates\backup\`），更早的会被自动清理以控制磁盘占用。
- **丢失发布签名私钥 = 无法再发布被现有安装信任的更新包**。这是签名机制的固有属性，
  不是缺陷；私钥必须离线备份。
- 更新包的版本必须**严格高于**当前版本；同版本或更低会被拒绝（`VERSION_NOT_NEWER`），
  因此**回退到旧版本需要手工替换程序文件**，不能在界面里做。
- 自检超时为 60 秒：重启后在 60 秒内无法通过回环自检的版本会被判定为失败并回滚。
  在极慢的磁盘上（冷启动 > 60 秒）可能因此回滚——可以调大 `--health-timeout-seconds`，
  但需要手工启动更新程序。
- 更新与回滚都会**恢复 `%LOCALAPPDATA%\LanDisk` 里的设置与密钥文件**
  （settings / shares / devices / recycle-index / transfers / favorites / preferences / secrets / tls）。
  缩略图缓存、日志、回收站内容与 fallback store **不在**备份范围内，因此不会被回滚影响。
